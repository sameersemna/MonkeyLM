# MISSION SPEC: Fix MonkeyLM Metrics & Add Agent Remediations

## Current Problem
The engine reports a '100% Success Rate' and 'PASSED' when the python test runner itself doesn't crash, but it completely buries the 19 critical application defects (SQL Injection vulnerabilities, unhandled javascript crashes like 'Cannot read properties of undefined') deep in the text. This is a false positive. We need to invert this logic and make the output machine-readable for downstream coding agents.

## Architectural Requirements

### 1. Invert Success Metrics State
- Locate where the final run summary dictionary is computed (likely `reports.py` or the runner engine).
- If any test step logs a `validation_failure` (like SQL injections), a `context_anomaly` (unhandled browser page errors), or a high/medium accessibility block, override that individual step's status metrics to `FAILED_APP_DEFECT`.
- Recalculate the overall `Success Rate`. It must ONLY read 100% if zero application bugs were encountered. If defects are found, force the global `Run Summary Status` to explicitly fail: `FAILED: [X] Application Defects Detected`.

### 2. Inject Structured `agent_context` JSON Blocks
- Refactor the Markdown text compiler script. 
- For every High or Medium severity defect ticket generated under the "# 🔧 Engineering Defect Tickets" section, append a code-fence JSON block matching this exact schema:

```json
{
  "agent_context": {
    "defect_type": "string_category",
    "severity": "HIGH|MEDIUM",
    "target_url": "exact_page_url",
    "target_selector": "playwright_compatible_selector",
    "reproduction_action": {
      "action": "click|type|submit_form",
      "payload_used": "value_or_fuzz_input"
    },
    "observed_error": "exact_console_log_or_api_stack_trace",
    "reremediation_instruction": "Strict backend validation check or frontend catch block fixing directions for an autonomous coding agent."
  }
}
```
