## Completed Step 5 — memory.py hardened
- Added `_sanitize_path_component()` — strict single-segment sanitizer for untrusted `domain`/`route` values: keeps only `[a-zA-Z0-9._-]`, **collapses `..` / multi-dot runs to `_`**, strips leading dots, rejects empty/`.`/`..`/`-`/`_` shapes (safe fallback), caps length at 128
- Hardened `_baseline_lookup_path()` (the only filesystem-path builder fed by untrusted URL-derived input): now resolves `base_dir` and `candidate` absolutely via `pathlib.Path` and enforces `candidate.relative_to(base_dir)` containment; any escape attempt is refused (warning logged) and falls back to the base dir
- **Path-traversal fix (real bug):** prior sanitizer `re.sub(r'[^a-zA-Z0-9._-]', '_', domain)` kept `.`/`-`, so a `domain`/`route` of `..` survived and `os.path.join(base, "..", ...)` escaped the base dir. Now neutralized.
- Added `_secure_atomic_write()` — writes to a secure 0o600 temp sibling file first, `fsync`s, `os.chmod`s, then `os.replace`s into place (atomic; no partial/corrupt targets on crash). Temp cleaned up on any failure.
- Added `_secure_atomic_write_json()` convenience wrapper (JSON + 0o600 + `os.replace`)
- Scope note: memory.py performs **no local disk writes** — all persistence is PostgreSQL/Redis/Qdrant over the network. `_baseline_lookup_path` is consumed only for logging; the actual baseline file writes live in `reporting.py` (Step 6), which will use these secure helpers + path containment.
- Committed in `b9c87e6`
